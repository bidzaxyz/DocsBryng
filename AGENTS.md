# Bryng documentation

- Docs use Mintlify with `docs.json` at the repository root and MDX content.
- Keep developer/API material separate from Business dashboard guides. Document only
  supported public contracts; never publish private backend routes or credentials.
- Use the approved Bryng logo assets unchanged and primary blue `#3B82F6`.
- Keep English articles and their mirrored Georgian versions in `ka/` aligned.
  Use `ka` for Georgian; retain the language dropdown until Mintlify supports it natively.
- Keep starter content minimal and truthful. Do not invent capabilities or dates.
- Work locally until the user approves the pending release. Pushing to a connected
  Mintlify branch may publish immediately; do not push without approval.
- Verify configuration, navigation targets, assets, and MDX before release.
